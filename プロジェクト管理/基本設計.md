# ローカル麻雀 Web アプリケーション 基本設計

対局形式と卓ルールは [要件定義.md](要件定義.md) に従う。

## 1. 技術構成

| 技術 | 用途 |
| --- | --- |
| TypeScript | 麻雀ルール、対局進行、CPUの判断、画面の実装 |
| React | 開始画面、対局画面、局結果と最終結果の表示、マウス操作の受付 |
| Vite | 開発環境とブラウザ向けファイルのビルド |

対局進行、和了判定、点数計算、CPUの判断、保存と再開はブラウザ内で完結する。対局用のバックエンド、API、サーバー側のデータベースは設けない。

対局進行とルール判定はReactから独立したTypeScriptの処理とする。画面は対局の状態と選択可能な操作を表示する。CPUは自分の手牌と公開情報から操作を選ぶ。将来の難易度追加はCPUの判断処理で行えるようにする。

## 2. 自動保存と削除

- 進行中の対局を1件自動保存する。ブラウザを閉じたりページを再読み込みしたりした場合は保存を残す。再開時は、保存した対局の手番や操作待ちの状態を復元する。
- 手動リセットを確定したとき、最終結果を表示するとき、プレイヤーがアプリ内の「タイトルへ戻る」を選んで開始画面に戻ったときに、対局の保存データを削除する。
- 最終結果を表示するときは、順位と持ち点を結果画面に渡してから保存データを削除する。結果は表示中だけメモリに持つ。

## 3. 起動と静的配信

ローカルでは起動用ファイルで静的ファイル配信を開始し、設定されたURLをブラウザで開く。配信先の設定は環境変数または `.env` ファイルから読み取り、アプリ内の設定値にまとめる。

| 環境変数 | ローカルの既定値 | 用途 |
| --- | --- | --- |
| `MJ_HOST` | `localhost` | ローカル起動時のホスト |
| `MJ_PORT` | `4173` | ローカル起動時のポート |
| `MJ_BASE_PATH` | `/` | Viteの `base` に渡す配信パス。サーバーの `/mahjong/` などに配置する場合はビルド時に指定する |

サーバーに配置するときは、ビルド済みの静的ファイルを Web サーバーで配信する。公開ドメインとポートは配信先の Web サーバーで設定し、ブラウザは実際に開いたアドレスを使う。アプリのコードに特定のホストやポートを埋め込まない。

[Vite公式ドキュメント 配信パス](https://vite.dev/guide/build.html#public-base-path)

## 4. 保存先

自動保存先はブラウザの `localStorage` とする。同じブラウザのプロファイルで同じオリジンを開くと、「続きから」で再開できる。ローカル起動と公開先はオリジンが異なるため、保存データはそれぞれの環境に持つ。

## 5. 対局画面と打牌操作

- プレイヤーの手牌は画面下に置き、CPU3席を左・上・右に配置する。各席の捨て牌と副露はその席の近くに並べ、現在の局、本場、供託、ドラ表示牌を中央付近で確認できるようにする。
- 自分の打牌番は、牌をクリックして選び、同じ牌をもう一度クリックすると打牌する。別の牌をクリックすると選択が移る。
- 打牌可能な牌を手牌から自分の捨て牌エリアへドラッグ＆ドロップしても打牌できる。ドラッグ中はドロップ先を示し、範囲外に落とした場合は打牌を取り消す。クリックとドラッグでは同じ打牌判定を使う。
- チー、ポン、カン、リーチ、和了、見送りのうち、選択可能な操作を手牌の近くに表示する。チーなどで組み合わせが複数ある場合は、候補を選んで確定する。
- 四人卓の一般的な配置を使う。卓全体の情報を一画面で確認できるようにし、視線を手牌の近くに置いたまま操作できるようにする。牌、配色、ボタン、背景はこのアプリ独自のデザインとする。

## 6. CPUの打ち方とテンポ

- 卓中央に現在の手番を表示し、その席の持ち点欄を強調する。CPUは手番の表示から0.75秒後に打牌などを行う。鳴きやロンの応答は待ち時間を挟まずに処理し、プレイヤーが操作できる場面では入力を待つ。
- CPU3席は共通の判断処理を使い、自分の手牌と公開情報をもとに、シャンテン数、受け入れ、狙える役やドラ、見込める点数を評価する。初版の難易度は1段階とし、打ち方を3タイプ用意する。
- 新規対局の開始時に、各CPUのタイプを3種類からそれぞれ等確率で抽選する。同じタイプが複数席に出る場合もある。割り当ては対局中を通して固定し、自動保存に含めて再開時に復元する。

| 打ち方 | 優先すること |
| --- | --- |
| 打点重視 | 役やドラが見込める形を残し、高い点を狙う。点数を下げてまで鳴くかは、手の進み方も見て判断する |
| 速度重視 | テンパイや和了に近づく手を優先する。鳴くのは、役を確保でき、手の進み方がよくなる場合を中心とする |
| バランス型 | 和了までの速さと見込める点数を比較し、手牌に応じて選ぶ |

## 7. 局結果と画面遷移

- 和了や流局で局が終わったら、局結果を表示してプレイヤーの操作を待つ。どの局でも同じ流れとし、CPUが和了した場合も点数の増減を確認できる。
- 対局が続く場合は「次の局」をクリックすると配牌と対局進行を開始する。対局終了が決まった場合は「最終結果へ」をクリックすると最終順位と持ち点を表示する。
- 局結果を表示している間にブラウザを閉じた場合は、再開時に同じ局結果を表示する。最終結果に進むときは、第2節のとおり保存データを削除する。

## 8. タイトル画面

- 保存データがある場合は「続きから」と「新規対局」を表示する。「続きから」をクリックすると、保存した対局の画面を復元する。
- 保存データがある状態で「新規対局」をクリックした場合は、前の対局を破棄してよいか確認する。確定すると新しい対局を開始し、保存を新しい対局で置き換える。キャンセルした場合はタイトル画面に戻り、前の対局を引き続き再開できる。
- 保存データがない場合は「新規対局」を表示し、クリックすると対局を開始する。
