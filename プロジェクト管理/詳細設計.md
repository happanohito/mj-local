# ローカル麻雀 Web アプリケーション 詳細設計

卓ルールは [要件定義.md](要件定義.md)、技術構成と画面の方針は [基本設計.md](基本設計.md) に従う。

## 1. 新規対局と配牌

1. 新規対局の開始時に、プレイヤーとCPUを含めた4席から、同じ確率で起家を1席選ぶ。起家を東1局の親とし、ツモ順に残りの席の起家からの順序を確定する。この順序は最終順位の同点判定で使う。CPU3席の打ち方もここで抽選する。
2. 各局の開始時に136枚の牌をシャッフルし、山と王牌を用意する。各席に13枚を配り、表ドラ表示牌を公開する。親に山から第1ツモを渡し、14枚にする。
3. 最初の打牌を受け付ける前に、親の14枚を判定する。第1ツモで和了形ができていれば天和のツモ和了が可能になる。プレイヤーが親ならツモ和了を選べるようにし、CPUが親ならツモ和了を選択する。プレイヤーが和了を見送った場合や和了形でない場合は、同じ手番で打牌などを選べる。追加のツモは行わない。
4. 連荘では親を維持し、親交代ではツモ順の次の席を親とする。新規対局ごとに起家を抽選し、各局の配牌直後にその局の親について天和を判定する。

子の地和は、鳴きや槓を挟まずに迎えたその席の第1ツモで判定する。第1ツモ済みかどうかを席ごとに記録し、局中の鳴きや槓の有無も記録する。 [天鳳公式マニュアル 四人打ちルール](https://tenhou.net/man/#RULE)

## 2. 局の状態と進行

| 状態 | 処理と次の状態 |
| --- | --- |
| 局開始 | 配牌し、親の第1ツモを渡す。第1ツモを含めて選べる操作を判定し、親の操作待ちへ進む |
| 自分の手番の操作待ち | 状況に応じて打牌、リーチ、ツモ和了、暗槓、加槓、九種九牌を受け付ける。打牌またはリーチ宣言牌が出たら、他家の確認へ進む。ツモ和了や九種九牌が成立したら局結果を確定する |
| 打牌後の他家の確認 | 打牌に対して各席が選べるロン・ポン・大明槓・チーを判定する。プレイヤーに選択肢がある場合は操作または見送りを待つ。全席の応答が確定してから、優先順位に従って処理する |
| 加槓の確認 | 加槓を確定する前に搶槓の可否を判定する。ロンがなければ加槓を確定し、嶺上牌をツモる。槓ドラの公開は参照ルールのタイミングで行う |
| 次の手番 | ロンが成立したら局結果へ。チー・ポンが成立したら鳴いた席が打牌する。槓が成立したらその席が嶺上牌をツモる。誰も鳴かず流局条件に達していなければ次の席が山からツモる |
| 局結果 | 和了または流局の精算を一度だけ行い、点数増減と続行・終了を確定する。プレイヤーの「次の局」または「最終結果へ」を待つ |
| 最終結果 | 確定した順位と持ち点を画面に渡し、保存データを削除して結果を表示する |

- ロンをポン・大明槓・チーより優先する。ロンの応答は全席分を確認し、ダブロンとトリプルロンを処理する。ポン・大明槓はチーより優先する。
- リーチ宣言牌に対するロンの確認が終わってから、成立したリーチの点棒を供託する。ロンが成立した場合は宣言者から供託を受け取らない。
- プレイヤーがロン可能な牌を見送った場合、同巡フリテンまたはリーチ後のフリテンを状態に反映してから進む。ツモ和了だけを見送って打牌の選択に戻る場合は、そのツモを見送ったことを記録し、再開時も同じ選択肢を表示する。
- 画面はCPUの手番を表示してから0.75秒後に、その手番の操作を対局処理へ進める。鳴きやロンの応答はそのまま処理する。再開時にCPUの手番が保存されていれば、同じ手番の表示から始める。画面とCPUは対局処理が提示した操作を選び、対局処理が現在の状態でその操作が有効かを確認する。画面に渡す情報は、プレイヤーが参照できる内容に限る。

## 3. 保存と再開

対局を再開できるよう、その時点の状態を `localStorage` の1件の保存データにまとめる。

| 保存する内容 | 用途 |
| --- | --- |
| 保存形式のバージョン、起家、プレイヤーの席、CPUのタイプ | 保存形式を識別し、席順とCPUの打ち方を復元する |
| 局、親、本場、リーチ供託、各席の持ち点 | 点数と局進行を復元する |
| 山と王牌の牌順、各席の手牌・副露・捨て牌、公開済みドラ表示牌 | 同じ牌配置とツモ順を維持する |
| 現在の状態と手番、各席の第1ツモの有無、リーチ・一発・フリテン・鳴きや槓の記録 | 各役と操作の成立条件を再現する |
| 確認中の打牌・加槓牌、入力済みの応答、未応答の席 | 鳴きやロンの選択を途中から再開する |
| 精算済みの局結果と次に進む先 | 局結果を再表示し、点数の二重精算を防ぐ |

- 配牌と第1ツモが確定したとき、操作や応答が確定したとき、局結果が確定したときに、状態をひとまとまりで保存する。ドラッグ中やクリックで選んだだけの牌は画面上の一時的な選択とする。
- 再開時は保存した状態を読み込み、同じ操作待ちまたは局結果に戻す。保存済みの起家や山を使い、配牌のやり直しや点数の再精算を防ぐ。
- 手動リセット、最終結果の表示、アプリ内で「タイトルへ戻る」を選んだときに保存データを削除する。

## 4. 和了判定と点数計算

### 4.1 和了形・役・ドラ

1. 和了牌、手牌、副露、和了方法、親と風、リーチ・一発、ツモの種類などの局面を受け取る。ロンでは、河に残る捨て牌に加えて鳴かれた自分の捨て牌も使い、同巡フリテンとリーチ後のフリテンを確認する。
2. 四面子一雀頭、七対子、国士無双の形を調べる。通常形は副露を固定し、残りの牌から可能な面子と雀頭の分け方をすべて求める。和了牌をどの面子や雀頭に使うかで待ちや符が変わる場合は、それぞれ評価する。
3. 各候補の役・役満を判定する。通常役と役満がどちらも成立しない場合は和了できない。喰い下がり、門前限定、役の複合は参照ルールに従う。候補が複数ある場合は、和了者が受け取る和了点が最も高い候補を採用する。
4. 和了牌と副露を含む和了手について、表ドラ・槓ドラ・裏ドラ・槓裏・赤ドラを種類別に数える。有効な表示牌1枚ごとに対応するドラを数え、同じ牌への重複も加算する。裏ドラと槓裏はリーチ和了時のみ有効。表示牌の次は数牌の1から9、風牌の東南西北、三元牌の白發中それぞれの順で循環する。
5. 通常の和了は、役の翻数とドラの合計から点数を求める。役満が成立した場合は役満の個数で和了点を決め、ドラの内訳は表示用に保持する。四暗刻単騎や国士無双十三面待ちなども各1倍とし、異なる役満が複合した場合はその個数に応じて加算する。 [天鳳公式マニュアル 四人打ちルール](https://tenhou.net/man/#RULE)

### 4.2 符・基本点・支払い額

- 通常形は副底の20符に、門前ロンの10符、ツモの2符、刻子・槓子・役牌の雀頭・待ちの符を加え、10符単位で切り上げる。連風牌の雀頭は4符。ロン牌で完成した刻子は明刻として扱う。平和ツモは20符、七対子は25符固定、加符のない副露ロンは30符とする。
- 基本点は `符 × 2^(翻 + 2)` とする。1〜4翻で基本点が2,000点以上になる場合と5翻は満貫として、基本点を2,000点にする。切り上げ満貫は採用せず、30符4翻・60符3翻は通常式で計算する。6〜7翻は基本点3,000点、8〜10翻は4,000点、11〜12翻は6,000点、13翻以上は数え役満として8,000点。役満で和了した場合の基本点は `8,000 × 役満の個数` とする。
- 支払う席ごとに次の倍率を基本点に掛け、100点単位で切り上げる。本場と供託はこのあと別に計上する。 [天鳳公式マニュアル 四人打ちルール](https://tenhou.net/man/#RULE) · [Mリーグ公式戦ルール 第6章](https://m-league.jp/about/)

| 和了方法 | 支払う席と倍率 |
| --- | --- |
| 親のロン | 放銃者が6倍 |
| 子のロン | 放銃者が4倍 |
| 親のツモ | 子3席が各2倍 |
| 子のツモ | 親が2倍、ほかの子2席が各1倍 |

### 4.3 局の精算と順位

- 和了点は各席間の支払いとして計算し、本場と供託を別項目で記録する。ダブロンでは和了点を2人分それぞれ計算し、本場と供託は放銃者からツモ順で先の和了者に配分する。大三元・大四喜の包がある場合は、天鳳の責任払いの規定に従い、本場の支払者も調整する。
- 通常流局は聴牌者を判定し、聴牌者とノーテン者が両方いる場合に3,000点を各グループ内で均等に分配する。形式聴牌も参照ルールに従って判定する。流し満貫が成立した場合は、成立者ごとの満貫ツモ相当額を計算して差し引く。本場の加点や供託の受け取りは発生せず、連荘は親の聴牌で決める。途中流局はノーテン罰符を発生させない。
- 局内の全支払いを集計してから各席の持ち点に一度だけ反映し、トビと東4局の終了条件を判定する。終局が確定した場合は残り供託を最終首位に加え、確定した順位と持ち点を最終結果に渡す。供託を含めた点数の総計は常に100,000点とする。

## 5. CPUの判断

### 5.1 入力と候補

- 対局処理から、自分の手牌と副露、各席の公開情報、現在選べる操作、対局開始時に割り当てたCPUタイプを受け取る。公開情報には捨て牌、副露、リーチ、ドラ表示牌、持ち点、局・本場、残りツモ枚数を含む。
- 合法なツモ・ロンがある場合は、CPUのタイプにかかわらず和了する。それ以外は、打牌やリーチ、鳴き、槓、見送りなどのうち、対局処理が提示した操作だけを比較する。
- 鳴き候補は、実際に副露した形で次の合法な打牌まで評価し、見送り後の手と比較する。鳴いた手に現時点で見込める役がなくなった場合は候補から外す。見送りより評価が高い場合に鳴く。
- 暗槓・大明槓・加槓は、見えていない嶺上牌や追加ドラを得点に加えず、槓をしたあとの手の形を評価する。リーチは、リーチ宣言牌ごとに、リーチする形と同じ牌を捨ててリーチしない形を比較する。リーチ棒1,000点と、以降の打牌が制限されることも判断に含める。

### 5.2 評価項目とタイプ差

| 評価項目 | 比較する内容 |
| --- | --- |
| 手の進み方 | 通常形・七対子・国士無双のうち可能な形についてシャンテン数を求め、テンパイに近い形を評価する |
| 受け入れ | シャンテン数が減る牌の残り見込み枚数を合計する。テンパイ時は和了形になる牌を調べる。自分の牌と公開済みの牌を差し引き、鳴かれた捨て牌は副露と重複して数えない |
| 見込める点数 | 現在の待ちや手の形から狙える役と、手に残る赤ドラ・公開済みのドラを評価する。テンパイ時は待ちごとに和了点を見積もる。リーチ和了時に公開される裏ドラは見積もりに使わない |
| 安全性 | 相手がリーチしている場合は、相手の捨て牌にある牌を安全と判断して評価に加える。複数人がリーチしている場合は、それぞれについて判定する |

各項目を共通の尺度にそろえて重み付きで合計する。下の数値を初版の調整開始値とし、高いほど判断への影響が大きい。安全性はリーチしている相手がいる場合だけ使う。

| CPUタイプ | 手の進み方 | 受け入れ | 見込める点数 | 安全性 |
| --- | ---: | ---: | ---: | ---: |
| 打点重視 | 3 | 2 | 4 | 2 |
| 速度重視 | 4 | 3 | 1 | 2 |
| バランス型 | 3 | 2 | 2 | 2 |

- 同点なら、鳴き・槓・リーチの候補より見送りや通常の打牌を優先する。打牌候補同士ではシャンテン数、受け入れ枚数、牌の固定順で決める。保存して同じ局面から再開しても、同じ入力に対して同じ判断になる。
- CPUの判断は画面と対局進行から分ける。新しい打ち方や難易度は、評価の重みや候補の比較方法として追加できるようにする。

## 6. 実装時に確認する動作

- 4席のどの席でも起家になれ、再開しても起家とCPUのタイプが維持される。
- 親の第1ツモで天和が成立した場合、最初の打牌より前にツモ和了を選べる。連荘で始めた局でも同じ判定を行う。
- 子の第1ツモで地和の条件を満たす場合と、それ以前の鳴き・槓で条件を失った場合を区別する。
- 鳴き・ロンの選択待ちで閉じて再開した場合、同じ牌に対して選択できる。局結果で再開しても点数が二重に動かない。
- 最終局の局結果で閉じた場合はそこから再開でき、最終結果を表示したあとに再度開くと「続きから」が表示されない。
- 子の30符4翻ロンは7,700点。子の25符2翻ツモは親800点、ほかの子が400点ずつ。親の単独役満ツモでは子3席が各16,000点を支払う。いずれも本場と供託は別に計上する。
- 赤5が表ドラと槓ドラの両方に該当する場合、その1枚だけでドラ3翻になる。役も役満もなければドラがあっても和了できない。
- ダブロンで1人目の和了点を払った直後に放銃者がマイナスになる場合も、2人目の点数まで反映してからトビと最終順位を判定する。
- 同じ局面で、速度重視は役が残ってテンパイに近づく鳴きを選び、打点重視は高い役を残せる門前を選ぶケースを確認する。速度重視でも、役の見込みがなくなる鳴きや、鳴いても手が進まないケースでは見送れることを確認する。
- すべてのCPUタイプが、和了可能なら和了し、合法な候補の中から操作を選ぶ。相手の伏せた手牌や残りの山の内容は判断用データに含めない。
